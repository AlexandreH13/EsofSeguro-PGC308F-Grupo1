## Elicitação de Requisitos

Documento usado para listar os requisitos levantados. Cada requisito funcional e não funcional está identificado por um código único.

---

**Requisitos Funcionais**

| ID    | Descrição                                                                                                                                   |
|-------|---------------------------------------------------------------------------------------------------------------------------------------------|
| RQF1  | Permitir um promotor do estado realizar acesso com suas credenciais institucionais                                                          |
| RQF2  | Usuário pode pesquisar mídias disponíveis de um processo                                                                                    |
| RQF3  | Usuário seleciona a mídia desejada para transcrição                                                                                         |
| RQF4  | Usuário pode acompanhar o status da transcrição da mídia (assíncrono)                                                                       |
| RQF5  | Usuário pode visualizar as transcrições já realizadas agrupadas por processo                                                                |
| RQF6  | Usuário pode acessar uma transcrição com status "finalizada"                                                                                |
| RQF7  | Usuário pode selecionar uma transcrição finalizada para usar como contexto na interação com a Inteligência Artificial disponível no sistema |
| RQF8  | Usuário pode fazer o download da transcrição em formato .docx                                                                               |
| RQF9  | Usuário pode deletar uma transcrição da sua lista de transcrições                                                                           |
| RQF10 | Usuário pode enviar perguntas à Inteligência Artificial e receber respostas baseadas na transcrição selecionada como contexto               |
| RQF11 | Usuário pode encerrar sua sessão no sistema                                                                                                 |

---

**Requisitos Não Funcionais**

| ID        | Nome                              | Descrição                                                                                                                                                                                                                                                                                                                                  |
|-----------|-----------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **RQF1** | **Autenticação/Autorização** | Permitir um promotor do estado realizar acesso com suas credenciais institucionais |
| RQF1.1 | Autenticação/Autorização | O sistema deve validar as credenciais institucionais do usuário antes de permitir o acesso |
| RQF1.2 | Autenticação/Autorização | O sistema deve permitir acesso às funcionalidades conforme as permissões do usuário autenticado |
| RQF1.3 | Autenticação/Autorização | O sistema deve impedir o acesso de usuários não autenticados às informações dos processos |
| **RQF2** | **Privacidade** | Usuário pode pesquisar mídias disponíveis de um processo |
| RQF2.1 | Privacidade | O sistema deve permitir o acesso às mídias somente para usuários autorizados no respectivo processo |
| RQF2.2 | Privacidade | O sistema deve impedir o acesso não autorizado às mídias e transcrições dos processos |
| RQF2.3 | Privacidade | O sistema não deve armazenar o contexto da conversa com a I.A. após o encerramento da conversa |

| **RQNF3** | **Desempenho**                    | Usuário seleciona a mídia desejada para transcrição                                                                                                                                                                                                                                                                                        |
| RQNF3.1   | Desempenho                        | O sistema deve permitir o upload de mídias até 80MB                                                                                                                                                                                                                                                                                        |
| RQNF3.2   | Desempenho                        | O tempo máximo da transcrição de uma mídia deve ser de 1 hora                                                                                                                                                                                                                                                                              |
| RQNF3.3   | Desempenho                        | O chat com a I.A não deve salvar o contexto da conversar quando o usuário encerrar a mesma                                                                                                                                                                                                                                                 |
| RQNF3.4   | Desempenho                        | Ao iniciar um chat com a I.A, a transcrição da mídia deve ser automáticamente passada como contexto                                                                                                                                                                                                                                        |
| **RQNF4** | **Escabilidade**                  | Usuário pode acompanhar o status da transcrição da mídia (assíncrono)                                                                                                                                                                                                                                                                      |
| RQNF4.1   | Escabilidade                      | O sistema deve permitir uploads simultâneos de diversos usuários                                                                                                                                                                                                                                                                           |
| RQNF4.2   | Escabilidade                      | O sistema deve permitir um usuário enviar mais de uma mídia para transcrição                                                                                                                                                                                                                                                               |
| RQNF4.3   | Escabilidade                      | O sistema deve suportar uma média de 2.000 transcrições diárias                                                                                                                                                                                                                                                                            |
| RQNF4.4   | Escabilidade                      | O sistema de filas deve possuir duas filas para transcrições, sendo uma fila para mídas grandes e outra fila para mídias menores e com transcrição rápida                                                                                                                                                                                  |
| **RQNF5** | **Confiabilidade**                | O sistema não deve perder solicitações nem transcrições diante de falhas de seus componentes ou dos serviços externos, e deve informar o usuário quando não conseguir concluir uma operação                                                                                                                                                |
| RQNF5.1   | Confiabilidade                    | O Módulo I.A só deve confirmar a mensagem na fila depois de gravar o status final da transcrição (finalizada ou falha). Se ele cair no meio do processamento, a mensagem deve voltar à fila para reprocessamento automático                                                                                                                |
| RQNF5.2   | Confiabilidade                    | O reprocessamento de uma mensagem deve ser idempotente: a mesma solicitação processada mais de uma vez não pode gerar duas transcrições nem duas chamadas à I.A para a mesma mídia                                                                                                                                                         |
| RQNF5.3   | Confiabilidade                    | Em falha da I.A externa, o Módulo I.A deve fazer até 3 novas tentativas com espera crescente (30 segundos, 2 minutos e 10 minutos). Esgotadas as tentativas, ou atingido o limite de 1 hora (RQNF3.2), a transcrição deve receber o status falha com o motivo                                                                              |
| RQNF5.4   | Confiabilidade                    | Se o Backend concluir a cópia da mídia para o Storage mas não conseguir publicar na fila, deve tentar publicar de novo até 3 vezes. Se a falha persistir, deve remover a cópia do Storage e registrar a solicitação com status falha. Não podem existir registros na fila sem mensagem correspondente nem arquivos no Storage sem registro |
| RQNF5.5   | Confiabilidade                    | Se o Sistema Processos ou o provedor de identidade estiver fora do ar, as sessões ativas devem continuar acessando as transcrições já finalizadas, e o usuário deve ver uma mensagem que identifique o serviço indisponível                                                                                                                |
| RQNF5.6   | Confiabilidade (disponibilidade)  | O serviço deve ter disponibilidade mínima de 99,5% em horário de expediente (dias úteis, das 7h às 19h), medida mensalmente                                                                                                                                                                                                                |
| RQNF5.7   | Confiabilidade (recuperabilidade) | O registro de transcrições e o Storage devem ter backup diário, com perda máxima de dados (RPO) de 24 horas e tempo máximo de recuperação (RTO) de 4 horas                                                                                                                                                                                 |
| **RQNF6** | **Integridade**                   | O sistema deve detectar qualquer alteração indevida em mídias, transcrições e mensagens da fila entre a origem e o usuário, antes de usar o conteúdo                                                                                                                                                                                       |
| RQNF6.1   | Integridade                       | O Backend deve calcular o hash SHA-256 da mídia ao copiá-la para o Storage e enviá-lo na mensagem da fila. O Módulo I.A deve recalcular o hash do arquivo baixado e recusar a transcrição, com status falha, se os valores divergirem                                                                                                      |
| RQNF6.2   | Integridade                       | Depois do status finalizada, nenhum componente pode alterar o arquivo da transcrição. Uma correção exige uma nova solicitação de transcrição                                                                                                                                                                                               |
| RQNF6.3   | Integridade                       | Toda transcrição com status finalizada deve ter o arquivo correspondente no Storage. Ao detectar um arquivo ausente ou com hash diferente do registrado, o Backend deve mudar o status para falha com o motivo e gerar um evento para auditoria                                                                                            |
| RQNF6.4   | Integridade                       | O arquivo .docx exportado deve conter exatamente o texto da transcrição armazenada e trazer, no rodapé, o identificador da transcrição e o hash do texto, para permitir a conferência do documento com o original                                                                                                                          |
| RQNF6.5   | Integridade                       | Antes de copiar uma mídia para o Storage, o Backend deve verificar que o formato real do arquivo corresponde ao declarado e que a varredura antimalware não encontrou ameaças. Se qualquer verificação falhar, o Backend deve recusar a solicitação sem gravar o arquivo                                                                   |
| **RQNF7** | **Auditoria**                     | Usuário pode selecionar uma transcrição finalizada para usar como contexto na interação com a Inteligência Artificial disponível no sistema                                                                                                                                                                                                |
| **RQNF8** | **Usabilidade**                   | Usuário pode fazer o download da transcrição em formato .docx                                                                                                                                                                                                                                                                              |
| **RQNF9** | **Manutenibilidade**              | Usuário pode deletar uma transcrição da sua lista de transcrições                                                                                                                                                                                                                                                                          |
